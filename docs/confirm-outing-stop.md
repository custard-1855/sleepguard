# 外出と停止の確認 仕様(Android)

2026-10-26 に合意した仕様。同日に実装した。

## 目的

「今夜は外出」と「停止」を一度押しで効かないようにし、勢いで見守りを外せないようにする。
ただし README の方針「解除対策はしない」は変えない。手間はかかるが止められる、にとどめる。

## 全体

- 対象はアプリ画面の「今夜は外出」、22時の入浴の通知の「外出中」、アプリ画面の「停止」
- 時間帯に関係なく、いつ押しても確認を出す(朝6時以降の外出はその夜に効くので、日中だけ一度押しにすると抜け道になる)
- 「帰宅した」と「開始」は一度押しのまま(見守りを強める側なので)
- ユーザー補助をオフにする・アンインストールするといった止め方は塞がない
- Mac は変えない(外出・停止のボタンがない)

## 今夜は外出

- 「今夜は外出しますか?」「今夜は入浴の通知・0:50の予告・1時のロックが止まります。」
- 10秒のカウントダウンのあと「外出する」が押せる。「やめる」で取り消し
- 待っている途中で画面を離れたら取り消し
- 入浴の通知の「外出中」は、アプリ画面を開いてこの確認をすぐ出す(通知のボタンでは何段階も聞けないため)

## 停止

- 文言を変えて3回聞く。待ち時間はつけない
  1. 「停止すると、もう一度『開始』を押すまで通知もロックも動きません。停止しますか?」
  2. 「今夜の見守りも止まります。本当に停止しますか?」
  3. 「本当に本当に? 寝る時刻を守るために入れたアプリです。」
- 確認のたびに「停止する」と「やめる」の左右を入れ替える(同じ場所の連打で抜けられないように)
- 途中で「やめる」を押すか、戻る・画面を離れたら最初からやり直し
- 1時〜6時は押せない。緊急解除(記録が残る)を通らずに全部を止められてしまうため。夜中に必要なときは緊急解除の30分を使う
- 0:59 に確認を始めて1時すぎに押し切った場合も停止しない(押すたびに時刻を確かめ直す)

## 実装メモ

- 停止の確認の流れは `StopConfirm` に置き、`StopConfirmTest` でテストする。Android には触らない
- 1時〜6時の判定は `Schedule.canStop`(`canGoOut` と同じ形)
- 停止の確認のボタンは AlertDialog の標準ボタンを使わず自前で並べる。OEM がボタンの並びを変えることがあり、左右の入れ替えが効かなくなるため
- 外出の確認のカウントダウンは `Schedule.GO_OUT_WAIT_MS`
- 入浴の通知の「外出中」は `OutingReceiver` への broadcast をやめ、`MainActivity` を `ACTION_GO_OUT` で開く
