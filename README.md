# SleepGuard

作業がきりよく終わらず、気づくと深夜になっている人のための Mac / Android 用ツールです。
22時に入浴を促し、0時から寝る準備を促し、1時以降も使っていたら画面をロックします。

## 方針

- **作業は壊さない**: 画面ロックは画面を消してパスワードを求めるだけで、スリープはしません。tmux の中のジョブ、ビルド、ダウンロード、ssh 接続などはそのまま動き続けます。
- **音は鳴らさず、ネットも遮断しない**: 通知とダイアログ、画面ロックだけで促します。
- **解除対策はしない**: 手間はかかりますが、止めたいときは止められます(Android の「停止」は3回の確認のあと押せます。1時〜6時は「停止」を押せませんが、確認画面の「緊急で使う」で30分はロックを外せます)。勢いで押せないようにはしますが、ユーザー補助をオフにする・アンインストールするといった止め方は塞ぎません。強制ではなく、区切りをつけるきっかけを作るためのものです。
- **現地時間で判定**: 時刻は端末のタイムゾーン設定で判定するので、出張や旅行先でもそのまま使えます。

## スケジュール

| 時刻 | Mac | Android |
|---|---|---|
| 22:00〜 | 使っている間、10分おきに「入浴済み」ボタンつきのダイアログ(4分で自動的に閉じる)。ダイアログ後に15分離席しても入浴済み扱い | 使っている間、15分おきに通知。「入浴済み」を押すと今夜はもう出ない |
| 0:00 | 通知 | 通知 |
| 0:50 | 予告の通知 | 同じ |
| 1:00〜 | 使っていたら通知し、10分後も使っていたら画面ロック。以後6時まで、操作するたびにロック | 使っていたら通知し、10分後も使っていたら確認画面を出してロック。以後6時まで、ロック解除するたびに確認画面 |
| 1:00〜で使っていない | 何もしない | 何もしない |

Mac は無操作が2分未満なら「使っている」とみなします。

## Mac

```sh
cd mac
sudo ./install.sh      # 入れる
sudo ./uninstall.sh    # 外す
```

`install.sh` は次の2つを root:wheel の所有で置き、launchd(root)から `sleepguard.sh` を毎分実行させます。常駐するプロセスはなく、22時〜6時の外ではスクリプトが時刻を見てすぐ終わります。

- `/Library/Application Support/SleepGuard/sleepguard.sh`
- `/Library/LaunchDaemons/com.sleepguard.agent.plist`

以前の版は `/usr/local/sleepguard` に置いていました。`/usr/local` は Homebrew の環境で一般ユーザーの所有になっていることがあり、root で動くスクリプトをすり替えられる恐れがあるため移しました。`install.sh` は旧配置先が残っていれば消します。`uninstall.sh` は新旧どちらの配置先も、夜ごとの記録(`/var/db/sleepguard`)も消します。

### 前提条件

- 「システム設定 → ロック画面 → スクリーンセーバの開始後またはディスプレイがオフになったときにパスワードを要求」を「すぐに」にしてください。これが「すぐに」でないと、画面が消えるだけでロックされません。
- 通知が出ないときは「システム設定 → 通知 → スクリプトエディタ」を許可してください(osascript の通知はこの名前で出ます)。

### 時刻や間隔を変える

`sleepguard.sh` 冒頭の設定欄で変えられます。変えたら `sudo ./install.sh` をもう一度実行します。

| 変数 | 既定値 | 意味 |
|---|---|---|
| `BATH_START` / `BATH_END` | 2200 / 2359 | 入浴ダイアログを出す時間帯(HHMM) |
| `BATH_INTERVAL` | 600 | 入浴ダイアログの間隔(秒) |
| `BATH_AWAY` | 900 | ダイアログ後にこれだけ離席したら入浴済みとみなす(秒) |
| `LATE_START` / `LATE_END` | 100 / 559 | 画面ロックの対象時間帯(HHMM) |
| `ACTIVE_IDLE` | 120 | 無操作がこの秒数未満なら使用中とみなす |
| `LOCK_GRACE` | 600 | 1時以降の通知から画面ロックまでの猶予(秒) |

時刻は HHMM を数値で書きます。先頭の0は付けません(1:00 なら `100`)。

### ログと動作確認

- ログ: `/var/log/sleepguard.log`
- 一般ユーザーで実行すると、時刻と無操作時間を指定して、通知もロックもせずログだけ出せます。`SG_DRY_RUN=1` と `SG_STATE_DIR` は必須で、どちらかが欠けていると何もせず終了します。root で実行したときは `SG_*` をすべて無視して本番どおりに動くので、`sudo` は付けないでください。

  ```sh
  SG_DRY_RUN=1 SG_USER=$USER SG_STATE_DIR=$(mktemp -d) SG_IDLE=5 \
    SG_NOW=$(date -j -f "%Y-%m-%d %H:%M" "2026-10-13 01:05" +%s) ./sleepguard.sh
  ```

### テスト

```sh
cd mac
./test.sh
```

一般ユーザーで実行します(`sudo` は付けません)。上の dry run で時刻・無操作時間・ログイン中のユーザーを変えながら `sleepguard.sh` を呼び、ログに出た通知・ダイアログ・ロックを確かめます。ケースごとに一時ディレクトリを使うので、インストール済みの状態には触れません。ケースごとに PASS/FAIL を表示し、1件でも失敗すると終了コードが0以外になります。

## Android

1. Android Studio で `android` フォルダを開き、同期が終わったら実機を繋いで実行します(minSdk 28 = Android 9 以上)。
2. アプリを開いて、上から順に押します。
   - 「1. 通知を許可」
   - 「2. ユーザー補助を有効にする」→「SleepGuard」を有効にします。通知も画面ロックもこのユーザー補助サービスが行うので、オフだと何も動きません。Android 13 以降で灰色になって押せない場合は、「設定 → アプリ → SleepGuard → 右上のメニュー → 制限付き設定を許可」をしてから戻ってください。
   - 「3. 開始」
   - 夜中に音声を聴くアプリがあれば、「音声のアプリを選ぶ」で選んでおきます(任意。1時〜6時は選べません)。
   - 端末の「緊急SOS」(電源ボタンを素早く5回押す)を有効にしておいてください。ロック中に待たずに通報できるのは、これとロック画面の「緊急通報」だけです(ほかの連絡は、確認画面の「緊急で使う」で30秒待ってから)。場所は機種で違い、「設定 → 安全と緊急」などにあります。押す回数も機種の設定に従います。
3. 常駐の通知は出ません。再起動やアプリの更新のあとも、システムがユーザー補助サービスを接続し直すので自動で動きます(「停止」を押したあとは、もう一度「開始」を押すまで動きません)。

### 外出モード

食事・移動・旅行などで夜に出かけるときに使います。アプリの「今夜は外出」か、22時の入浴の通知の「外出中」を押すと、確認が出ます。10秒待つと「外出する」が押せるようになり、押すと入ります(待っている途中で画面を離れたら取り消し)。1時〜6時は入れません。その夜だけ有効で、翌朝6時に自動で切れます(何泊かの旅行では毎晩入れます)。位置情報などでの自動判定はしません。

| 時刻 | 外出中 |
|---|---|
| 22:00〜 | 入浴の通知を出さない |
| 0:00 | 普段どおり通知 |
| 0:50 | 予告を出さない |
| 1:00〜 | 使っていたら一度だけ「外出中でも2時までには寝ましょう」と通知。ロックはしない |

外出中は「帰宅した」ボタンつきの通知が出たままになります。帰ったら、この通知かアプリの「帰宅した」を押します(外出モードのときだけ押せます)。

- 0時台までに押したら、普段の流れに戻ります(22時台なら入浴の通知も再開します)。
- 1時以降に押したら、2時以降に使っていたら通知し、10分後も使っていたら画面をロックします。2時以降に押したときは、押した時点からこの流れになります。

### ロック中の確認画面

1時以降にロックの対象になると、すぐロックする代わりに確認画面を出します。以後6時まで、ロックを解除するたびにこの画面が出ます。10秒操作しないか、戻る・ホーム・履歴で離れるとロックします。

- **ロックする**: すぐロックします。ロック画面には、緊急SOSと「緊急通報」の案内つきの通知が出ます。
- **緊急で使う**: 「本当に緊急ですか?」の確認と30秒の待ちのあと、30分ロックしません。回数の制限はありません。この間もアプリの「停止」は押せません。使った時刻はアプリ画面の「緊急解除」に出ます。110・119 はこれを通さず、ロック画面の「緊急通報」からかけられます。
- **音声を聴く**: アプリ画面の「音声のアプリを選ぶ」で選んだアプリを開きます。回数の制限はなく、そのアプリが前面にあるあいだは時間に関係なくロックしません。ほかのアプリに移ると、また確認画面が出ます。ホーム画面と履歴の画面では出ないので、履歴からスワイプで閉じられます。アプリを選んでいなければボタンは出ません。1時〜6時はアプリを選び直せません。アプリ画面には「選択済み」とだけ出て、アプリ名は表示しません。
- **アラームを設定**: 端末の標準の時計のアプリを開きます。選ぶ手順はなく、回数の制限もありません。時計のアプリが前面にあるあいだはロックしません。ほかのアプリに移ると、また確認画面が出ます(ホーム画面と履歴の画面は除く)。時計のアプリが見つからないか、複数あって標準が決まっていなければボタンは出ません。

確認画面が出せなかったとき(端末の制限など)は、普段どおりロックします。仕様は `docs/emergency-unlock.md` にあります。

### 設定の変更と、やめるとき

- 時刻は `app/src/main/java/dev/sleepguard/Schedule.kt` にまとまっています。
- 動作確認は `Schedule.kt` の時刻を数分後に変えてビルドするのが早いです。
- やめるときはアプリの「停止」を押すか、アンインストールします。「停止」は文言を変えて3回確認し、そのたびに「停止する」と「やめる」の左右が入れ替わります。途中で「やめる」を押すか画面を離れたら最初からです。1時〜6時は押せません。
- アプリが持つ権限は、通知とユーザー補助(画面ロックと、時間割の評価)だけです。ユーザー補助は画面の内容を読み取らない設定で、画面の切り替えのイベントから前面にあるアプリの名前だけを読みます(「音声を聴く」で選んだアプリや時計のアプリを使っているかの判定のため)。ネット接続の権限は持っていないので、利用状況が外に送られることはありません。
